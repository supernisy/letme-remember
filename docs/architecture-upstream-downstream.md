# 架构决策：与宿主 Agent 记忆的关系（上游缓存 / 下游权威）

> 状态：已定（2026-11-11）｜决策人：supernisy｜影响文件：governance spec、docs/

## 决定

letme-remember 与宿主 Agent 平台（WorkBuddy / DSH 等）的内置记忆**不做平行系统**，而是**单向上下游**：

- **上游**：宿主平台的现场会话记忆（如 WorkBuddy 注入的 user memory）。它是「现场速记员」，含大量噪声、易被覆盖、绑定当前工具。
- **下游**：letme-remember。它是「档案室」，跨工具权威沉淀，蒸馏后结论级、带时间轴、可审计。

数据只**单向流动**：上游 →（蒸馏 / 净化 / 软判断）→ 下游。**下游永不回写上游。**

## 为什么（解决"两套记忆得出相反结论"的冲突）

同一件事若在上下游各记一份且互不同步，会出现两个相反结论（例：上游记「只看杭州」、下游记「可接受上海」），Agent 各读各的、给出矛盾建议。

解法：**只有下游能定义"当前生效的真相"，冲突靠时间轴 + 取代链把并列关系变成先后关系**——新结论写入时，旧的标记 `superseded_by` 失效，检索只回最新生效那条，旧结论自动沉底。上游缓存若与「你本人 + 下游」冲突，以上游之外的权威为准。

## 落地阶段（现状）

- **现阶段**：只做**只读导入**——把宿主平台已积累的记忆一次性蒸馏进下游做存量（`import` 语义，单向、不反向同步）。
- **架构接口已留**：上游/下游的关系、单向蒸馏方向、取代链裁决权，写进 governance spec 作为正式约束。
- **未做（留待后续）**：自动/定时同步、宿主平台主动推送、双向上游回写。想接时再按此接口实现，不锁死方向。

## 边界（Non-goals）

- 不做双向同步（下游不推回上游）。
- 不做实时联动（现阶段导入是批量/人工触发，非事件驱动）。
- 不声称"取代"宿主平台记忆——上游仍是现场交互的最快路径，下游是跨会话权威层，各司其职。
