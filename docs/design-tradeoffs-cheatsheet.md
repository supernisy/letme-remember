# letme-remember 设计取舍速查卡

> 读者：用户本人（长期回看）｜用途：一张卡看懂「这个项目为什么这么设计、每个关键取舍背后的理由」
> 状态：随项目演进更新（最新决策排在上方）｜最后更新：2026-11-15

---

## 0. 一句话定位

做一个**通用的长期记忆仓库**，由用户主动控制：指定哪段结论进长期记忆；进得去、查得到、能追溯来源、能改能删。**不只服务 WorkBuddy**，还要被 DSH、千问办公等宿主加载。

**根本前提（三条，定了不再论证）**：
1. 大模型无状态，「记住」= 每轮把记忆重新拼回上下文。
2. 长期/短期是**位置**概念，不是时间概念：上下文之外 = 长期，当前窗口 = 短期。
3. 记忆的工程本质 = **每轮重新决定给模型看什么**，不是「让模型记住什么」。

---

## 1. 核心原则（每条都是刻意为之）

| # | 原则 | 为什么 |
|---|---|---|
| P1 | **文件是唯一真相源**，索引只是可重建缓存 | 索引损坏/删掉可随时重建，零知识丢失 |
| P2 | **结论必须带理由**，拒绝裸结论 | 防止「只记判断、不记为什么」的不可审计记忆 |
| P3 | **永不物理删除**，只失效 + 归档 | 过期结论走时间轴，`--as-of` 能查回历史真相 |
| P4 | **读路径零 LLM、零网络** | 检索不消耗 token、不依赖网络，永远可用 |
| P5 | **要不要人审批，由代码写死的规则决定**，不由大模型拍板 | 大模型只做软判断，裁决权收回到代码 |
| P6 | **格式封闭**，不引入 YAML/JSON 解析器 | 防「悄悄重解释」，多宿主共同读写才不被曲解 |
| P7 | **单向上下游**，下游永不回写上游 | 避免「两套记忆得出相反结论」 |

## 2. 记忆模型（一条记忆长什么样）

### 2.1 粒度

- **最小单位是「结论级」**：一条判断 + 理由 + 适用条件 + 来源 + 时间。
- 粒度**按类型定义**，不是全局一刀切。

### 2.2 字段（frontmatter 固定 12 个）

`name` `abstract` `type` `created` `updated` `valid_from` `invalid_at` `superseded_by` `weight` `author` `links` `provenance`

正文固定两节：`## 结论` + `## 理由`。

### 2.3 时间维度（治「过期结论」）

一条记忆 = 一个**有效期区间**：`valid_from`（何时成立）→ `invalid_at`（何时失效）→ `superseded_by`（被谁取代）。

- 过时结论：标记失效 + 归档，**不物理删除**，可 `--as-of` 查历史。
- 错误/无效记忆（写错的、测试残留）：**可真正删除**，但属高影响不可逆，走 L2 强制人工审批 + 审计留痕。

### 2.4 变量 vs 常量（重要区分）

| 类别 | 例子 | 治理方式 |
|---|---|---|
| 认知/偏好类（变量） | 地域偏好、个人底线、人际策略 | 标注「以用户最新表态为准」，保留被取代余地 |
| 工程/技术类（常量） | 退出码约定、安全红线、确定性规则 | 可记铁律；若曾正确后过时，仍走时间轴 |

治理时**优先审查变量类**——这类最易被记成一刀切，导致检索误用过期结论。

## 3. 类型分类（两套，别混淆）

### 3.1 内容类型：旧九类 → 新三类型（CoALA）

来源：**CoALA 认知架构**（Princeton 2023，讲 AI Agent 记忆系统设计），也是认知科学里「语义/情景/程序」记忆的经典划分。

**旧九类（v1 早期，已废弃）**：profile / preference / entity / decision / fact / experience / event / reference / procedure。

**新三类型（当前标准）**：

| 类型 | 英文 | 一句话 | 回答的问题 | 衰减 |
|---|---|---|---|---|
| 语义 | semantic | 稳定的事实、偏好、结论、教训、方法 | 什么是对的 | 不衰减 |
| 情景 | episodic | 某次具体事件/面试/报告的复盘索引 | 发生了什么 | 会衰减 |
| 程序 | procedural | 可重复执行的流程、规则、怎么做 | 怎么做 | 不衰减 |

**合并规则**（`schema.py` 的 `LEGACY_TYPE_MAP`）：旧九类里凡「稳定/可复用/不过期」的归 semantic；「指回某个具体事件或原文」的归 episodic；「怎么做」的归 procedural。

**人分类的判据**（3 秒口诀，顺着问三个问题）：
1. 这是个「结论/事实」吗 → 是 = semantic（删了以后想不起来）
2. 这是在「讲一次具体的事」吗 → 是 = episodic（正文在别处，这条只指路）
3. 是「教我怎么干」吗 → 是 = procedural（能照着一步步操作）

### 3.2 健康四维：体检打分，不是贴标签

来源：**mem-gc**（给 AI Agent 记忆做垃圾回收的开源项目）。

| 维度 | 各占 | 低分 = 什么问题 | 处理动作 |
|---|---|---|---|
| 新鲜度 | 25% | 内容过时、被新事实覆盖 | 更新 / 标记失效 |
| 唯一性 | 25% | 同件事记了好几条 | 去重合并 |
| 一致性 | 25% | 两条记忆说法打架 | 找矛盾源，保留新的 |
| 检索效用 | 25% | 记下后从没被召回 | 降权 / 删除 |

**两套的关系一句话**：类型是「固定标签，一分终身」；健康是「动态打分，随时在变」。

## 4. 存储形态（载体 + 结构 + 索引，三维正交）

| 维度 | 决策 | 取舍理由 |
|---|---|---|
| 载体 | Markdown 文件唯一真相源 | 人可读、可 git、可迁移 |
| 结构 | typed 记忆 + 条目内 `links` 字段近似关系 | v1 **不做真知识图谱**（不引入 Neo4j/Graphiti） |
| 索引 | SQLite 可重建缓存（FTS5 关键词） | 增量同步靠内容哈希；删 `.index/` 不丢知识 |

**数据目录布局**（在代码仓库之外）：
```
~/.letme-remember/data/
  store/      活跃记忆（.md，一文件一条）
  archive/    归档记忆（失效后移入）
  MEMORY.md   索引目录（一句话摘要，可重建）
  .index/     可重建索引缓存（index.db + vec + access）
  proposals/  待审提案
  staging/    导入候选卡片暂存区
  audit.log   审计日志
  config.json 数据目录内配置
```

**隐私边界**：公开仓库只放代码/规范/测试/虚构示例；真实记忆在私有数据目录，单独维护一个私有 git 做审计。**克隆仓库 ≠ 拿到记忆**。

## 5. 写入：三审流程（核心防线）

| 审 | 谁 | 干什么 |
|---|---|---|
| 第一审 | 脚本 | 格式校验 + 红线形状硬拦（密钥类打码），命中即打回，不问人 |
| 第二审 | 大模型（可插拔） | 软判断：产出结构化体检报告，**只报告、不落库、不裁决** |
| 第三审 | 代码分级裁决 | 按固定阈值落入 L0 / L1 / L2 |

### 5.1 六个升级触发器（大模型软判断覆盖）

`conflict`（与库中结论矛盾）· `high_impact`（高影响不可逆）· `ambiguous`（歧义）· `novel_type`（新类型）· `compliance`（合规边界）· `uncertain`（不确定表述）——任一项命中即抬高等级。

### 5.2 三级裁决

| 等级 | 触发条件 | 处理 |
|---|---|---|
| L0 | 无冲突、无缺失、低重要、高置信 | 自动入库，事后留审计 |
| L1 | 命中任一触发器 / 中重要 / 中置信 | 进待审队列，异步批量审批 |
| L2 | 高影响 / 碰合规 / 删除作废已有 / 低置信 | 强制人工逐条拍板 |

**关键纪律**：裁决权在代码（固定阈值），LLM 不自行拍板要不要人审。

### 5.3 红线（两层分离，最重要的一条澄清）

> 「不愿对外公开的私人敏感事实」**不是永不入库的红线**，而是「可入库 + 输出口径随人随场景变」。

- **入库层红线（真·硬拦）**：只拦「密钥类」（api_key/token/password/sk- 前缀等）→ 形状规则正则硬拦，写入前自动打码。
- **敏感事实（可入库，不拦）**：个人经历、家庭情况等，照常入库，作为「对我完整了解」的一部分。
- **输出策略层**：同一事实对外按「对方是谁 + 什么场景」取不同口径。**v1 后专门设计，当前挂起未写死**。

## 6. 检索：三层路径 + 排序公式

### 6.1 三层路径（确定性从高到低）

| 路径 | 是什么 | 依赖 |
|---|---|---|
| ① 常驻索引注入 | 会话开始注入 MEMORY.md 一句话目录 | 无（确定性，不调模型） |
| ② 关键词检索 | FTS5 BM25 + 两字短词子串兜底 | 无 |
| ③ 语义检索 | 向量余弦相似度 | 本地 embedding（可选） |

### 6.2 排序公式

```
score = 相关度 × 权重 × 新鲜度
```

- 相关度 = 关键词(BM25) 与 语义(余弦) 融合，用 RRF；语义不可用时自动退化纯关键词。
- 新鲜度 = 指数衰减 + 半衰期（默认 90 天），有下限兜底（`recency_floor`），旧记忆**沉底但不消失**。

### 6.3 语义检索的服务化（v1.3，重要取舍）

- 向量模型**只加载一次、常驻内存**，召回毫秒级。
- 常驻服务：本地 TCP `127.0.0.1:7867`，每行 JSON，零新依赖（标准库 socket）。
- 启动**强制离线加载**（`HF_HUB_OFFLINE=1`），避免联网重试拖到 100 秒。
- **双层兜底**：客户端 2 秒超时 / 服务异常 → 自动降级纯关键词，主流程永不卡死。
- 生命周期绑定会话 + 空闲自退（默认 2 小时）+ 端口锁防重复拉起。

## 7. 注入方式（怎么拼回上下文）

**混合模式（业界主流）**：常驻索引 + 按需读正文。

- **被动注入**：会话开始（SessionStart）自动把 MEMORY.md 索引注入，**字节硬上限**（默认 8KB），超预算按权重截断。
- **主动查询**：大模型按需调工具读某条记忆正文，而非预先塞全文。

---

## 8. 淘汰策略（不是 TTL 硬删）

**时间衰减 + 权重 + 手动归档** 三结合：

- 时间衰减：越旧越沉底（自动）。
- 权重：重要记忆衰减慢、排名靠前（人工介入）。
- 手动归档：用户主动归档，彻底离开检索。
- **自动淘汰只做「提案」，需人确认，不自动删。**

---

## 9. 审计（trace）

**复用 git 作为审计日志**：每次维护 = 一次 commit，可查谁改的、何时改的、改了什么，可 `git revert` 撤销。数据目录内单独一个私有 git。

## 10. 存量导入（蒸馏不是搬运）

- **一条日志 ≠ 一条结论**，须提炼成「结论 + 理由 + 适用条件 + 来源 + 时间」。
- **单向只读**：只读源，不改写/删除/重建宿主既有记忆。
- **预处理分三类**：格式合规可转 / 待裁决 / 明确排除；只做机器能确定性判断的事。
- **卡片 ≠ 记忆**：候选卡片落 `staging/` 暂存区，不进真相源、索引、检索结果。
- **报告不含原值**：只记数量、来源类别、规则编号、缺失字段。
- 人确认后的卡片仍走与常规写入相同的三审，**不提供绕过审批的批量直写**。
- `provenance` 记来源类别 + 原始日期 + 导入批次；`created` 记导入时间；`valid_from` 记原结论成立时间；`author` 记导入来源标识。**四者不混用**。

### 10.1 长文本分块蒸馏（v2 方向④，Map-Reduce）

超长转写（面试/会议流水）单次蒸馏会超长截断、丢信息，故分块处理：

- **范式 = Map-Reduce**（业界标准，LangChain 等）：分块 → 每块独立提炼候选 → 合并。要的是「N 条结论级记忆」而非「一段流畅摘要」，天然可并行可合并。
- **分块策略 = 说话人轮次/段落边界**，不是「逐句 embedding 的语义分块」。理由：访谈/面试/会议类转写，按「讲话人 + 时间戳 + 空行」段落累积、逼近上限才切，天然保证「一个问答不拆两半」。语义分块慢、要调阈值、块大小不可控，是最后手段。
- **合并去重 = 确定性 name 级去重**（分块蒸馏时同一结论可能在不同块重复出现，同 name 后出现覆盖先出现）；深层语义去重（ADD/UPDATE/NOOP）交给现有 consolidate 落库时做，**不新造一套去重**。

### 10.2 结论级增量 diff（识别「这次比上次深在哪」）

多次相似面试「讲得越来越深」，系统原来只能去重、不能提取增量。补的是**显式语义 diff**：

- **判据**：把「上一版结论集」和「本次新候选」交 LLM 对比，产出三张清单——`added`（本次新增主题）/ `deepened`（上次已有、这次补了细节）/ `unchanged`（基本一致）。
- **为什么是「结论级」而非「句子级」**：Mem0 的四操作（ADD/UPDATE/DELETE/NOOP + 语义召回）项目里 consolidate 已有，缺的不是「怎么判操作」而是「显式列出这次深化了什么」。句子级 diff + 溯源（MemoryLake 快照 diff 那套）对个人场景是过度设计。
- **复用不重造**：合并去重复用 consolidate 判定；diff 只是「新增一个显式对比步骤」。

## 11. 与 agent-memory 的差异（自建点，不照抄）

来源借鉴：[tigerless-labs/agent-memory](https://github.com/tigerless-labs/agent-memory)。**只取其已验证的设计，不 fork。**

| 差异 | 内容 |
|---|---|
| D1（关键） | 它的红线只拦密钥；我们扩展为「敏感事实可入库 + 输出策略分层」 |
| D2 | 沿用「不用 YAML、自造封闭 frontmatter」当护栏 |
| D3 | 它面向编码 agent 多宿主；我们面向个人长期记忆 + 求职 + DSH + 千问办公 |
| D4 | 它没有「存量异构记忆一次性迁移」场景；我们须处理来源追溯 + 原始日期 + 批次撤销 |

## 12. 上游/下游关系（架构决策）

- **上游** = 宿主平台现场记忆（WorkBuddy 注入的 user memory）：现场速记员，噪声多、易覆盖。
- **下游** = letme-remember：档案室，跨工具权威沉淀。
- 数据**单向流动**：上游 →（蒸馏/净化/软判断）→ 下游，**下游永不回写上游**。
- **冲突靠时间轴 + 取代链收敛**：新结论写入时旧的标 `superseded_by` 失效，检索只回最新生效那条，把并列关系变成先后关系。

## 13. GUI 可观测性（v2 方向，最近的决策）

设计参考：可观测性分层 + Google SRE 黄金四信号 + mem-gc 健康四维。

### 13.1 三层下钻

| 层 | 回答什么 | 内容 |
|---|---|---|
| L1 总览 | 系统是否良好运行、有什么急迫问题 | 一句话健康判定 + 系统状态灯 + 分级待办 |
| L2 定位 | 哪类/哪条出了问题 | 类型分布可下钻、诊断列表 |
| L3 诊断 | 这条具体哪里不对 | 单条详情：结论/理由前置 + 三根真实诊断指标 |

### 13.2 告警分级（P0-P3，每条必带动作）

P0 紧急 · P1 重要 · P2 观察 · P3 信息。

### 13.3 设计纪律

- **3-3-3 规则**：每页 ≤3 面板、每面板 ≤3 指标、每个指标一句话。
- **结论前置**：卡片标题用 `abstract`（人话），机器名降级为灰色小字；详情「结论/理由」加粗前置。
- **识别索引式指针记忆**：正则 `/见原文|见.*\.md|详见/`，这类是 episodic 索引，点击跳原文而非展开。
- **serve 三态**：running（绿）/ idle-exit（黄）/ error（红），靠状态文件 `.index/serve.state` 判断。
- **健康四维真实化**：新鲜度/一致性/检索效用有真实指标；唯一性（去重）未落地，标注「无法计算」，**不造假数据**。

---

## 14. 边界（明确不做的事）

- 不自动写入（写入需触发 + 审批）。
- 不自动淘汰（只做提案，人确认）。
- 不做真知识图谱（links 字段近似）。
- 不做跨设备云同步（纯本地，除非触发复议条件）。
- 不做双向同步（导入为单向一次性迁移）。
- 不存会话原文语料（只存结论，不存语料）。
- 不声称「取代」宿主平台记忆（上游仍是现场最快路径）。

## 15. 悬挂问题（未结论，边走边定）

1. **fork 与否**：暂不 fork，先借鉴；看清差异后再定。
2. **输出策略层具体设计**：敏感事实「多口径」怎么存、怎么按人/场景选口径——v1 后专门展开。
3. **多宿主常驻服务复用**：DSH 接入时是否复用同一实例（端口复用 + 引用计数）——留待 DSH 联调。
4. **宿主写入口切换**：导入完成后各宿主何时改直接写本仓库——另立提案。
