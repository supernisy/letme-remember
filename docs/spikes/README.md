# 技术探针记录（Spike Log）

> 读者：开发 AI 与后续维护者｜用途：把「技术不确定」变成有证据的结论，并显式留下未解决项

## 这份记录是什么

Spike（技术探针）是**给闸门输送事实的旁路**，不是第五个开发阶段，也不是实现代码。
每条探针只回答一个问题、代码一次性、结论必须回写到规范或设计文档，再过一遍准出闸门。
实验代码不进主源码树；探针失败或未得出结论时，保留「残留不确定」而不是假装它不存在。

固定格式五项：**待回答问题 / 成功判据（动手前写） / 证据 / 回写位置 / 残留不确定**。

## 尚未验证、明确留到后续的范围

- 本地 embedding 模型（向量检索）的安装、中文效果与索引体积：**v1.1 探针**，触发条件是语义检索成为真实需求。
- 真知识图谱引擎（时序图）对「过期结论」的收益：触发条件是「时间戳 + 取代链」压不住时。
- 多宿主（不同 Agent 平台）实际接入后的并发写入与格式一致性：v1 只提供同一份格式契约，未做跨宿主实测。
- 存量记忆预处理在真实数据上的三态分布与人工确认负荷：导入提案范围内再验证。

以上各项在验证前**不得被描述为已解决**，也不得据此扩展 v1 范围。
