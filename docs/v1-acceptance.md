# v1 验收记录

> 读者：开发 AI 与维护者｜用途：逐条核对《需求定稿》§7 的验收标准

## 核对结论

| §7 条目 | 结果 | 依据 |
|---|---|---|
| 1. 一句话能把某会话的结论存进去，也能一句话排除 | ✅ v1 范围内达成 | `mem record` 写入一条候选；不提交候选即排除。自动从会话提炼属于后续提案 |
| 2. 任一条记忆能回答：哪来的、什么时候写的、为什么这么定、何时可能失效 | ✅ | 文件头固定 12 字段：`provenance` / `created` / `updated` / 正文「理由」/ `valid_from` + `invalid_at` + `superseded_by` |
| 3. 存的东西不污染现有机制 | ✅ | 代码与记忆数据物理分离；数据目录默认在代码仓库外，私有 git 与索引缓存均独立于任何宿主既有配置 |
| 4. 任何一次写入都能撤销 | ✅ | 每次写入在私有 git 产生一条只含真相源文件的提交；`mem undo` 或标准 `git revert` 可恢复 |
| 5. 检索不用记文件名 | ✅ | `mem recall` 返回定位标识，`mem show <标识>` 读回完整正文 |
| 6. 红线（密钥类）在写入前被拦下；敏感事实可入库、对外输出口径按人/场景可控 | 🟡 前半达成，后半属后续提案范围 | 形状规则表（凭据类强制打码、标识符类默认告警）在写入前执行；输出策略层明确挂起 |
| 7. 导入条目能回答来自哪类旧文件、原结论何时成立、属于哪个批次、是否被人批准，且整批可撤销 | 🟡 字段与批次撤销达成；实际导入与人工裁决属后续提案范围 | `provenance` 三段语义 + `created` / `valid_from` / `author` 分离；`mem undo-batch` 整批恢复；存量导入另立 `import-legacy-memory` 提案 |

## 明确标注为后续提案范围

- 输出策略层：同一敏感事实按对象与场景取不同口径。
- 存量记忆导入：只读预处理、三态候选卡片、人工裁决、分批落库。
- 语义检索（本地向量）、自动提炼、自动淘汰、宿主写入口切换、真知识图谱。
- 多宿主接入后的并发写入实测。

上述各项在本次实现中**没有**被描述为已完成。

## 验证方式

- `python -m unittest discover -s tests -v`：单元与端到端测试，每项任务由测试里的 `@req` 标签点名。
- `python tools/gate.py`：准出闸门（断言完整性、需求到测试可追溯、测试全过、规范严格校验、隐私扫描、批准未漂移、探针残留不确定已记录）。
- `openspec validate --all`：规范结构与增量规范校验。
- 公开仓库敏感信息复查：示例、注释、测试用例、规则表样例、提交历史。

## 实测结果

- 单元与端到端测试：44 项全部通过。
- `openspec validate --all`：7 passed / 0 failed。
- 任务清单共 27 项，全部由测试里的 `@req` 标签点名。
- 隔离安装固定版本分词依赖后，中文写入与检索正常；禁用该依赖后降级路径仍返回结果。
