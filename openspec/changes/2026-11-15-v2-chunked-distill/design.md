# 方向④：超长文本分块蒸馏 + 结论级增量 diff

> 状态：待实现｜日期：2026-11-15｜来源：v2.0 方向草案 §4（超长文本蒸馏的分块 + 增量提取）

## Context（问题）

现有 `distill` 是**单次调用**：

1. 长面试转写（半小时~一小时，几万 token）会超过模型上下文上限，**截断丢信息**——前半段的结论蒸不出来。
2. 多次类似面试「讲得越来越深」，系统**只能去重、不能识别「这次比上次深在哪」**——因为每次蒸馏是独立单次调用，没有和上次的产物对比。

## 业界结论（已查，非臆想）

### 1. 长文本蒸馏范式 = Map-Reduce

LangChain 等框架对超长文本摘要只有两条成熟路线：

| 路线 | 做法 | 代价 | 适用 |
|---|---|---|---|
| Map-Reduce | 分块→各自提炼→合并 | 可能丢块间连贯性 | 结论/事实型抽取（**本项目**） |
| Refine | 逐块串行精炼 | 慢、不可并行 | 追求流畅叙事摘要 |

**本项目用 Map-Reduce**：目标不是「一段流畅摘要」，而是「N 条结论级记忆」，每条独立，天然可并行、可合并。

### 2. 分块策略 = 说话人轮次（speaker-turn），不是语义分块

转写分块专门指南明确：**访谈/面试/会议转写首选 speaker-turn 分块**——按「问答轮次/说话人切换」切，天然保证「一个问答不拆两半」。语义分块（逐句 embedding 算相似度）慢、要调阈值、块大小不可控，是最后手段。

**落地**：用规则识别问答边界（`Q:`/`A:`、时间戳、角色名、空行、Markdown 标题），**不逐句 embedding**。

### 3. 增量提取 = 补「显式 diff」，不是再造四操作

- **Mem0 四操作**（ADD/UPDATE/DELETE/NOOP + 语义召回旧记忆 + LLM 判）：本项目**已有**（consolidate 的 ADD/UPDATE/SUPERSEDE/NOOP + `find_related_entries` + `supersede_time_guard`），且比 Mem0 多了时间维度守卫。
- **MemoryLake memory-diff**（对比两个快照，列「改了什么」）：面向行为漂移根因，非面试进步。

**结论**：方向④的「增量」是补「**结论级 diff**」——同一项目多次面试，新旧候选交 LLM 对比，产出「本次新增/深化」清单，不做句子级溯源。

## Decisions

### D1：Map-Reduce 分块蒸馏

- 长文本 → 按问答/说话人轮次分块 → 每块用现有 `DISTILL_PROMPT` 提炼候选 → 合并去重。
- 合并去重**复用现有 consolidate**（ADD/UPDATE/SUPERSEDE/NOOP），不新造一套去重。

### D2：分块用规则识别问答边界（不逐句 embedding）

- 边界信号：`Q:`/`A:` 前缀、时间戳（`[00:12:34]`）、角色名（`面试官:`/`候选人:`）、空行、Markdown 标题。
- 块大小上限兜底：单块超过 token 上限时按句边界二次切分（避免单块超长仍截断）。

### D3：结论级增量 diff

- 同一项目多次面试：把「上一版结论集」与「这一版新候选」交 LLM，产出「本次新增/深化」清单。
- 只做结论级，不做句子级溯源（个人场景，句子级是过度设计）。

## Non-Goals

- 不做句子级 diff + 原文溯源。
- 不新造「同主题合并去重」——复用 consolidate。
- 不改模型选型、不改 `DISTILL_PROMPT` 的核心产出格式（仍产结构化候选）。
- 不做实时/事件驱动增量，保持批量触发。

## 落地形态

- 新模块 `lmr/chunk.py`：分块器（`chunk_transcript`）。
- 新模块 `lmr/incremental.py`：结论级 diff（`diff_conclusions`）。
- CLI：新增 `mem.py distill-chunk --file <长文本> [--dry-run]`；扩展 `batch-distill` 支持 `--chunk` 与 `--diff-against <上一版候选JSON>`。

## Open Questions

- 分块大小上限默认值（建议按模型上下文 75% 兜底，如 12000 token）。
- 增量 diff 的「上一版结论」从哪取：从库里按主题召回（复用 `find_related_entries`），还是显式传上一版候选 JSON。
