## Why

仓库目前只有《需求定稿》和 6 个能力规范，没有任何可运行的东西：「存一条结论、查得到、能追溯时间」这件事还没有真正发生过。规范先立、实现后补，现在需要一个最小闭环把三件事打通，作为向量检索、输出策略层、多宿主接入与存量记忆导入的共同地基。

## What Changes

- 新增一个命令行入口，提供六类操作：写入一条记忆、检索、查看正文、标记失效、重建索引、列出索引目录；读写都落在本地纯文本文件上。
- 新增仓库目录布局与记忆文件格式的正式契约：记忆文件放在哪个私有数据目录、怎么命名、文件头（frontmatter）有哪些字段、索引文件长什么样。
- 落地写入的第一道关卡：脚本格式校验 + 形状规则红线。凭据、私钥块、令牌、连接串与高熵串强制打码；机器可读标识符默认告警、打码可配置；叙述性私人事实不进红线。同时落地时间轴（有效期区间 + 取代链 + 按日期查历史真相）与不物理删除的失效归档。
- 落地关键词检索与「相关度 × 权重 × 新鲜度」排序；中文查询走预分词与短词兜底，读路径不调用大模型。
- 落地被动注入所需的索引文件生成，以及「一次写入 = 一次 git 提交」的可撤销审计。
- 把**代码仓库（公开）与记忆数据（私有、仓库外）分离**：公开仓库只含代码、规范与完全虚构的示例，真实记忆数据永不随仓库发布。
- 运行时依赖采用白名单：中文分词库为唯一纳入项且可降级，其余能力一律用标准库；依赖版本由声明文件固定。
- 为存量记忆导入预留文件头语义：`provenance` 记来源类别、原始日期与导入批次，`created` 为导入时间、`valid_from` 为原结论成立日期、`author` 为导入来源标识，三者不混用；导入本身另立提案。
- 本次不做：向量语义检索、输出策略层、自动写入、自动淘汰、后台维护进程、UI、跨设备同步、真知识图谱、存量记忆导入、新旧记忆双向同步。
- 无 **BREAKING** 变更：这是一个全新仓库，不改动任何宿主的既有行为，也不改写或删除宿主现有的记忆文件。

## Capabilities

### New Capabilities

- `cli`: 命令行接口契约——宿主与人通过它读写记忆；规定每个操作的输入、输出、错误条件、退出码、读路径零模型调用，以及中文查询必须可召回的约束。
- `store-layout`: 仓库目录布局与记忆文件格式契约——规定真相源文件的位置、命名、文件头字段、索引文件、失效归档、导入条目的来源与时间语义，以及代码与数据分离的边界。

### Modified Capabilities

- `write-approval`: 明确形状规则红线的完整覆盖范围（凭据与密钥类、机器可读标识符类）、两类处置方式（强制打码 / 告警可选打码）、误报抑制方式，以及「叙述性私人事实不进红线」的边界。三审流程与其他要求不变。

## Impact

- 新增一个可执行入口与一组本地脚本（语言与依赖见 design.md）。
- 新增一份固定版本的依赖声明文件；中文分词库缺失时自动降级，不影响可用性。
- 新增一个**代码仓库外的私有数据目录**：存放记忆正文、它自己的 git 审计历史、以及可重建的索引缓存；公开仓库不发布其中任何内容。
- 公开仓库里只新增代码、规范、测试与一份完全虚构的示例记忆。
- `write-approval` 规范中的红线要求按本提案调整；其余 5 个能力规范作为本次实现的验收依据。
- 不改变 WorkBuddy、DSH、千问办公现有的记忆读写行为；本仓库是独立的可选组件，宿主需主动接入。存量记忆文件在导入提案执行前保持原状。
