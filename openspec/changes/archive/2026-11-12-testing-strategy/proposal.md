## Why

项目已积累 116 项测试函数 + 20 项子测试（12 个测试文件），但它们是「散装」的：全部平铺在 `tests/` 根目录，没有 unit / integration / e2e 分层，没有 pytest 标记，没有覆盖率门禁，也没有一条「从零到整」的端到端验收流程。

用户明确要求：不要再做「小单元」的零散测试，要从头到尾走一遍「大单元」的整体功能测试；先按业界专业测试方案立规范，再跑全量回归。

此外，上一轮全量回归暴露出一个现实问题：语义检索引入后，测试套件在「依赖已装」的环境下会真加载 120MB 模型 + 联网重试，导致挂起（SIGTERM）。这暴露了**测试缺乏隔离性约束**——测试必须可脱离网络、模型、外部服务独立运行，否则回归就不可靠。

本 change 把「测试工程」作为独立的 capability 纳入 OpenSpec 管理，确立测试金字塔分层、全量回归基线、端到端验收、覆盖率门禁四项规范。

## What Changes

- **测试金字塔分层**：`tests/` 重组为 `unit/`（纯逻辑，毫秒级）、`integration/`（模块协作，秒级）、`e2e/`（真实命令全流程，分钟级）三层，配 pytest.ini 标记（`unit` / `integration` / `e2e`），支持按层分别执行。
- **全量回归基线**：把「116 项 + 20 子测试全过、约 60 秒」固化为回归基线；每次改动后必跑全量，作为不回归的硬门禁。
- **端到端验收流程**：定义一条「从零到整」的真实用户旅程（init → record → recall → show → inject --query → embed → serve → 语义召回 → invalidate → rebuild），作为发版前的完整验收。
- **覆盖率门禁**：引入 pytest-cov，设定覆盖率阈值（domain/service 层 ≥80%），定位未测死角。
- **测试隔离铁律**：所有测试可脱离网络/模型/外部服务独立运行；禁止在测试里真加载大模型或真联网。

## Capabilities

### New Capabilities

- `testing`: 新增，确立测试金字塔分层、回归基线、端到端验收、覆盖率门禁、隔离性五组要求。

## Impact

- `tests/` 目录重组为三层（文件移动，测试逻辑不重写，仅必要的 import 路径调整）。
- 新增 `pytest.ini`（注册标记、testpaths、覆盖率配置）。
- `requirements.txt` 增加测试依赖声明（pytest、pytest-cov，作为 dev 依赖说明）。
- 不改变任何业务代码行为；测试改造是纯工程结构变更。

## Non-goals

- 不重写现有 116 项测试的业务断言（仅做归类与隔离性修补）。
- 不引入 CI/CD 流水线配置（.github/workflows 等）——那属于后续独立变更。
- 不追求 100% 覆盖率（覆盖率是方向，不是考核口号）。
- 不改动被测业务代码的功能语义。
