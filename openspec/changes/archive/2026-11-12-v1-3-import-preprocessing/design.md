## Context

存量导入的「落库侧」已就绪（v1.2 的 store import 三字段、undo-batch、validate 校验、LLM 蒸馏、batch-distill）。本 change 补「预处理侧」，即需求定稿 §2.12 反复强调的只读预处理 + 三类判定 + 候选卡片暂存。

## Goals / Non-Goals

- Goals：只读扫描异构源 → 逐条判定三类 → 产出候选卡片（暂存区）+ 脱敏报告；幂等可重跑；不判定内容有效性。
- Non-Goals：不自动落库、不自动判内容有效、不做双向同步。

## Decisions

### D1：三类判定由「确定性规则」驱动，不引入 LLM

- 「格式合规可转」= 形状红线通过 + 字段完整 + 日期合法 + 类型可猜；
- 「待裁决」= 形状合规但存在需人判断的信号（类型无法确定、疑似取代关系、命中合规边界）；
- 「明确排除」= 日志流水、过程推演、重复备份、会话原文（按来源类别 + 启发式规则识别）。
- 理由：预处理 SHALL NOT 判定「结论现在是否成立」，那是人的事；机器只做能确定性判断的形状/格式层。
- 备选：让 LLM 参与三类判定——违反「内容有效只能人判定」的边界，排除。

### D2：卡片落暂存区，与真相源物理隔离

- 卡片写 `paths.staging/`（config.Paths 已有），真相源在 `paths.store/`；索引只扫 store/archive，天然不会把卡片编进索引或检索。
- 每个卡片带内容哈希（sha256）作为幂等键；重复预处理同源文件时，哈希相同即跳过，不重复产卡。
- 理由：隔离是「卡片不是记忆」的硬保证，靠目录布局而非约定。

### D3：报告脱敏——只记元信息，不记原值

- 报告字段：数量、来源类别、命中规则编号、缺失字段名；SHALL NOT 记正文、命中处原值、凭据形状原值。
- 理由：需求 §2.12「报告不含原值」；预处理报告可能被写进公开仓库或日志，必须天然不含敏感内容。

### D4：预处理命令只读，产出为「卡片 + 报告」两个产物

- 新增 `import-preprocess --source <dir|file> [--source-category <cat>] [--batch <id>]`：扫描源，产出卡片 JSON（staging）+ 报告。
- 人确认后的卡片，走既有 `distill` / `consolidate` 落库（复用三审），预处理命令本身不落库。
- 理由：命令职责单一——预处理只做「读取 + 判定 + 产出卡片」，落库是下一阶段人的动作。

## Risks / Trade-offs

- 启发式识别「日志流水/过程推演」可能误判——用「来源类别」作为主要判据（日志目录 → 明确排除），而非正文语义；误判可接受，因为卡片始终要过人确认。
- 幂等键用内容哈希，源文件即使改名/移动也能识别重复；但源内容微调会生成新卡——符合预期（内容变了就该重新审视）。

## Migration Plan

纯增量，无迁移。既有落库侧不动；staging 目录为空时预处理命令正常返回空结果。
